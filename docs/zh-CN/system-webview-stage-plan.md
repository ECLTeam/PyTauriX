# 第十三阶段：系统交互与 WebView 策略回调

状态：2026-11-07 用户明确要求“系统交互与完整能力开始实现”，已授权本地实现及验证。
本阶段作为完整能力工作的首批；后续协议、安全配置、IPC 取消/背压、菜单和官方插件继续按依赖拆批。
本次授权不包含提交、推送、发布或修改 ECL 正式工作区。

## 目标与选择

面向桌面 Python 宿主，先补足新窗口、资源请求和权限请求回调，同时收口已有真实系统交互证据。
保持锁定 Tauri 2.12.1 和 PyO3 0.29.3，默认 features 与依赖不变。
与直接开放 Rust 对象相比，采用不可变 Python 快照和显式返回值，避免借用 HTTP/原生对象逃出回调。
新窗口先支持上游 Allow/Deny；Create 涉及共享 WebView 环境/配置与同步建窗限制，单列未绑定。

## 实施与契约

1. 新增 `webview_requests.py`：HTTP 请求/响应快照、新窗口几何快照、权限种类及决策枚举。
   HTTP 头保留重复项及原始字节；响应替换须完整通过原生校验后一次提交，异常时返回空 500 并有序退出。
2. `window_builder.rs` 与独立回调模块接入三个上游钩子；窗口回调槽统一持有、销毁清空。
   原生注入来源，使用创建时的窗口代次弱引用，不按可复用 label 重新选择回调。
   回调同步且不能等待 GUI；错误/awaitable/非法返回时拒绝新窗口或权限，并沿既有错误通道归还 Python。
3. Python Builder、`_native.pyi`、根导出、运行时能力、迁移契约、指南和人工账本同步。
4. 增加真实 WebView 场景：页面请求资源、响应替换与重复头、window.open 拒绝/允许、定位权限拒绝、
   非法返回/异常/awaitable、销毁与退出后回调释放。资源钩子仅覆盖上游应用协议，不能冒充 HTTP 全网拦截器。
5. 调查托盘定位失败，保留像素和真实系统输入检查；增加自有源窗口到目标 WebView 的 OLE 文件拖放。
   焦点只在实际前台会话验证；DPI/系统主题切换不修改用户全局配置，缺少环境时明确保留待验收。

## 调查问题

- 13-01：下载回调原先按可复用标签查找窗口状态，旧下载可能查到同名新窗口回调。
  触发条件为下载与窗口销毁/同名重建交叉；应始终属于创建时代次。已改用创建时弱引用，随场景回归验证。
- 13-02：测试把绝对路径写入 `WindowConfig.dataDirectory`，上游仅接受相对路径且会忽略绝对路径，导致测试复用默认 profile。
  已增加显式 `data_directory` Builder 参数，使用临时目录并重新验证权限回调；不把默认目录的拒绝缓存算作策略证据。

- 13-03：系统已把键盘焦点交给目标 WebView 子控件，但 `is_focused()` 仍返回 False，导致动态窗口焦点验收失败。
  `system-interaction.log` 中修复前 `system=true/native=false` 可复现；Windows 查询改为前台 GUI 队列并核对父子窗口。
  新增局部 unsafe 仅为 Win32 状态读取：指向本地有效 GUITHREADINFO，HWND 按值查询，查询后再次校验资源代次。
- 13-04：自动隐藏任务栏在 UIA 查询间收回，UIA 根列表短暂不包含 Shell_TrayWnd，导致已存在的自有托盘定位失败。
  驱动改为从原生任务栏 HWND 获取 UIA 元素，并在查询期间保持真实指针位于通知区域所在任务栏；保留图标颜色与真实输入断言。

首轮专项结果：系统交互 9 项通过，策略正常场景与九种失败恢复通过，托盘正常及异常/awaitable 三个进程通过。
DPI/混合缩放与系统全局主题切换尚无对应设备或隔离会话，不修改用户全局显示配置。
